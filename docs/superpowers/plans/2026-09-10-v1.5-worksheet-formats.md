# Worksheet Formats (v1.5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a second Worksheet Format — "Realistic Thinking", a 1:1 rendering of the user's therapist's paper worksheet — as the default for new Thought Records, while keeping the existing 8-step flow as the selectable "Classic" format.

**Architecture:** Each `ThoughtRecord` gains a permanent `format` stamp (`'realistic' | 'classic'`) set at creation; a `worksheetFormat` setting (default `'realistic'`) only decides the format of *new* records, and every record is always viewed/completed/edited in its native format. Realistic Thinking data lives in new flat fields on `ThoughtRecord` (`negativeThought`, `beliefBefore`, `alternativeThought`, `beliefAfter`, `emotionNow`) plus a single entry in the existing `emotions` array for the before-emotion. Dexie migrates existing rows to `format: 'classic'`; backups bump to version 2 with version-1 files still importable (as Classic).

**Tech Stack:** React 18 + TypeScript, Vite, Dexie (IndexedDB), react-router (HashRouter), Tailwind, framer-motion, Vitest + React Testing Library (jsdom + fake-indexeddb).

## Global Constraints

- The Realistic Thinking wizard uses the therapist's wording **verbatim**: section names "Identifying negative thoughts" / "Gathering the evidence" / "Realistic Thinking"; questions "What was your thought?", "How much do you believe in this thought?", "What was your emotion?", "How strong was the emotion?", "Evidence for the thought", "Evidence against the thought", "What is your alternative thought?", "What is your emotion now?", "How strong is the emotion?".
- Question order follows the paper exactly: Situation → thought + belief → emotion + strength → (fork) → evidence for → evidence against → alternative thought + belief → emotion now + strength.
- Realistic Thinking records hold exactly **one** thought and **one** before-emotion; the after-emotion may be a *different* emotion. No Hot Thought, no distortions step.
- The `format` stamp is immutable after creation. No conversion between formats, ever. No migration of existing records beyond backfilling `format: 'classic'` + empty defaults for the new fields.
- The "Name the thinking pattern" toggle (`namePatterns` setting) applies to Classic only and is hidden in Settings while the Realistic Thinking format is selected.
- All percentages use the existing `IntensitySlider` (0–100, step 5). Emotions use the existing chips + custom free-text entry; both thought fields are free text (no chips).
- Run tests with `npx vitest run <path>` (the bare `npm test` starts watch mode). Full gate: `npx vitest run && npm run build`.
- Work happens on branch `feat/worksheet-formats`. Never commit to `main`.
- Follow the existing code style: 2-space indent, single quotes, Tailwind classes inline, tests colocated next to sources.

    createdAt: now,
    updatedAt: now,

  return (await getSetting(WORKSHEET_FORMAT_KEY)) === 'classic' ? 'classic' : 'realistic';

```ts
import type { ThoughtRecord, WorksheetFormat } from './types';

export type WizardStep =
  | 'situation'
  | 'emotions'
  | 'thoughts'
  | 'fork'
  | 'evidenceFor'
  | 'evidenceAgainst'
  | 'distortions'
  | 'balanced'
  | 'rerate'
  | 'negativeThought'
  | 'emotionBefore'
  | 'alternative'
  | 'emotionNow'
  | 'done';

export function stepsForMode(
  mode: WizardMode,
  format: WorksheetFormat,
  includeDistortions = true,
): WizardStep[] {
  if (format === 'realistic') {
    const restructure: WizardStep[] = ['evidenceFor', 'evidenceAgainst', 'alternative', 'emotionNow', 'done'];
    switch (mode) {
      case 'new':
        return ['situation', 'negativeThought', 'emotionBefore', 'fork', ...restructure];
      case 'complete':
        return restructure;
      case 'edit':
        return ['situation', 'negativeThought', 'emotionBefore', ...restructure];
    }
  }
  const restructure = (
    ['evidenceFor', 'evidenceAgainst', 'distortions', 'balanced', 'rerate', 'done'] as WizardStep[]
  ).filter((s) => includeDistortions || s !== 'distortions');
  switch (mode) {
    case 'new':
      return ['situation', 'emotions', 'thoughts', 'fork', ...restructure];
    case 'complete':
      return restructure;
    case 'edit':
      return ['situation', 'emotions', 'thoughts', ...restructure];
  }
}

export function initWizard(
  record: ThoughtRecord,
  mode: WizardMode,
  includeDistortions = true,
): WizardState {
  return { record, steps: stepsForMode(mode, record.format, includeDistortions), stepIndex: 0 };
}
```

```markdown
# 1. Worksheet formats are stamped per record, never converted

Date: 2026-09-10

## Status

Accepted

## Context

The app originally offered one worksheet structure (now "Classic"): multiple emotions,
multiple automatic thoughts with a hot thought, optional distortions, a balanced thought,
and a re-rating of the same emotions. The user's therapist works from a different paper
worksheet ("Realistic Thinking"): one thought with a 0–100% belief rating, one emotion,
evidence for/against, an alternative thought with its own belief rating, and a fresh
"emotion now" that may be a different emotion. Both formats must coexist: the therapist's
sheet as the default for new records, the original still available, and existing records
preserved.

The two shapes are not losslessly convertible in either direction: Classic has no belief
ratings; Realistic Thinking has nowhere to put non-hot thoughts or distortions.

## Decision

Every ThoughtRecord is stamped with its worksheet format at creation and keeps it for
life. The `worksheetFormat` setting only selects the format for *new* records. A record
is always viewed, completed, and edited in its native format; an Open Record completes
in the format it was started in. There is no conversion path between formats, and the
record list shows a mix.

Existing rows are backfilled to `format: 'classic'` (Dexie v3); backup files bump to
version 2, and version-1 backups import as Classic.

## Consequences

- No data loss and no migration risk when the setting changes.
- Display components (card, detail, wizard, done screen) branch on `record.format`.
- The record type carries both formats' fields, with the unused side empty/null.
- A future third format follows the same pattern: stamp, branch, never convert.
```
